# Drug Order QR Scanner Implementation Plan

## Inputs

- Approved design: `docs/superpowers/specs/2026-04-24-drug-order-qr-scanner-design.md`
- Existing lookup route: `src/app/dashboard/dutru-dat-hang/tra-cuu/page.tsx`
- Existing QR URL contract: `src/lib/drug-orders/qr-token.ts`
- Existing UI primitives: `Button`, `Dialog`, `Input`

## Goal

Add a `Quet QR` scanner dialog to the existing drug order QR lookup page. The scanner reads a QR value, normalizes it to the existing `?t=<token>` lookup URL, and lets the current server-side page continue to handle token validation, session checks, authorization, and result rendering.

## Steps

1. Install `@zxing/browser`.
2. Add `DrugOrderQrScannerDialog` as a client component.
3. In the component:
   - open the camera only while the dialog is open
   - decode QR frames through ZXing
   - accept absolute lookup URLs, internal lookup paths, and raw token values
   - route to `/dashboard/dutru-dat-hang/tra-cuu?t=<token>` after a valid scan
   - stop camera controls on close, unmount, or successful scan
   - show short errors for camera and QR parsing failures
4. Wire the scanner button into `LookupForm` on the existing lookup page.
5. Run lint and typecheck.

## Verification

- `npm run lint`
- `npx tsc --noEmit`
- Manual browser check on a secure origin or localhost:
  - scanner dialog opens
  - camera stops after close
  - QR generated by `DrugOrderQrCode` navigates to lookup result
  - manual `Ma don` lookup still works
  - invalid QR text stays in the dialog with an error
